# ADR 0003：版本化 Workflow 与 Run 工作区

状态：接受（设计）；实现按 M2 及后续阶段推进。

## 背景

开发任务需要保留用户现有工作，支持独立审查、故障恢复和流程持续改进。固定角色团队或随时改写运行中的模板，都会让状态与验证难以核对。

## 决策

Loom 管理目标、派发和证据；Agent 承担按需配置的职责。首版实现 feature/debug，其余四类先保留规格。

一个写 Run 默认一个独立 Git worktree 和一个 writer。创建前记录 Git 与内容基线；明确用户未提交修改是否进入任务。工作区隔离和上下文隔离分别管理，worktree 不视为安全沙箱。

Run 固定 workflow 版本，计划变化单独递增 planVersion。模板可以重构，通过任务评估后发布新版本；新版本默认只应用于新 Run。迁移显式执行，核对副作用并使受影响验证失效。

## 后果

需要实现工作区所有权、内容指纹和恢复核对。复杂并行采用独立任务工作区与串行集成，不从增加角色数量起步。

流程优劣依据真实完成、返工、人工接管、耗时和用量判断。Agent 自述、步骤减少、历史文章性能数据均不足以证明改进。

详见 [工作区生命周期](../WORKSPACES.md) 与 [角色和演进](../ROLES_AND_EVOLUTION.md)。

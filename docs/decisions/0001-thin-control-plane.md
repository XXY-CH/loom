# ADR 0001：薄控制层与隔离专业执行

状态：设计原则保留，尚未实现；具体执行层由 [ADR 0002](0002-embedded-pi-runtime.md) 修订为内嵌 pi-durable，待 Runtime Spike 验证。

## 决策

控制层拥有状态转移、权限范围、预算、依赖和证据门禁。专业 worker 拥有领域推理。新任务类型优先组合现有职责，不默认增加新 Agent。

## 原因

开发任务跨设计、代码与测试，单个长上下文容易混淆职责。确定性状态机便于恢复和追踪；隔离推理便于控制知识范围。但开放式需求不能假设总能确定性分类，因此单独设计结构化规划入口。

## 代价

需要适配器、结构化产物和持久状态；职责拆分会增加交接开销。简单任务必须允许短路径。

## 来源与边界

借鉴 Meta Thin Orchestrator 博客，见 references/meta-thin-orchestrator。Meta 案例面向数据流水线；将其推广到通用开发工作台是本项目提案，尚未证明同等收益。此前讨论的“几百行足够”没有工程验证，不作为计划承诺。
